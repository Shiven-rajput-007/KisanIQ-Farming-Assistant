# KisanIQ — Final Production Repair Audit (Phase 1)

This audit documents every defect, root cause, required fix, and verification mechanism identified across the KisanIQ production codebase.

---

## Audit Matrix

| Issue ID | Area | File(s) | Root Cause | Fix Plan | Verification |
|---|---|---|---|---|---|
| **AUDIT-01** | **i18n Default Language** | `frontend/src/i18n/config.ts`, `frontend/src/types/i18n.ts` | `i18n.init` had hardcoded `lng: ... \|\| 'mr'` and `LanguageDetector` falling back to browser navigator rather than Hindi. | Set default `lng: 'hi'`, set `fallbackLng: { default: ['hi', 'en', 'mr'] }`, remove browser language auto-detection override. Save manual selection to `localStorage`. | Launch app with clean localStorage → verify active language is Hindi (`hi`). |
| **AUDIT-02** | **Hardcoded Marathi in English View** | `frontend/src/pages/home/index.tsx`, `frontend/src/pages/weather/index.tsx`, `frontend/src/pages/market/index.tsx`, `frontend/src/pages/soil-testing/index.tsx`, `frontend/src/components/layout/app-header.tsx` | UI JSX contained raw Devanagari text instead of translation keys (`t(...)`). When user changed language to English, hardcoded strings remained Marathi. | Extract every hardcoded string to its respective namespace JSON (`home.json`, `weather.json`, `market.json`, `soil.json`, `common.json`) across `hi`, `en`, and `mr`. Replace in TSX with `t(...)`. | Automated key parity test + manual language switch HI → EN → MR → HI. |
| **AUDIT-03** | **i18n Missing Keys Parity** | `frontend/src/locales/{en,hi,mr}/*.json` | `assistant.json` and `common.json` had mismatched keys between English, Hindi, and Marathi, causing untranslated fallbacks. | Synchronize all 10 namespace files across `hi`, `en`, and `mr`. Ensure 100% key parity. | Create automated test script `tests/i18n.test.ts` verifying zero missing keys. |
| **AUDIT-04** | **Weather API Production Failures** | `server/services/weatherService.ts`, `server/controllers/weatherController.ts` | Single provider (Open-Meteo) experienced intermittent cold-start timeouts and unhandled network drops. No secondary provider fallback existed. | Implement robust two-provider architecture: Primary = WeatherAPI.com (`WEATHER_API_KEY`), Secondary = Open-Meteo (`OPEN_METEO_BASE_URL`). Strict coordinate validation, caching, and clear error status `WEATHER_UNAVAILABLE`. | Live automated test with real coordinates (e.g. 28.6139, 77.2090). |
| **AUDIT-05** | **Weather Location & Geocoding** | `server/controllers/weatherController.ts`, `frontend/src/hooks/useWeather.ts` | Authenticated farmer profiles with textual district/state but missing GPS coordinates failed with 400 instead of attempting live geocoding. | Implement OpenStreetMap Nominatim geocoding in backend if coordinates missing; if geocoding fails, return structured `LOCATION_REQUIRED`. Hook displays clear prompt with retry. | Test unconfigured user, geocoded user, and GPS user flows. |
| **AUDIT-06** | **CEDA Agmarknet Mandi Over-Restriction** | `server/services/marketService.ts`, `frontend/src/pages/market/index.tsx` | `queryMarketPriceRows` strictly required matching both commodity, district, AND state. If no records matched the exact district, query returned empty array ("No verified mandi data found"). | Implement tiered search: (1) Commodity + District, (2) Commodity + State, (3) Commodity Nationwide. Clearly label geographic scope. | Test known commodity in district, then in other districts of same state → verify broader real records return. |
| **AUDIT-07** | **CEDA Live Data Diagnostic** | `server/scripts/verify-ceda-live.ts`, `server/package.json` | Previous test script lacked standard status lines for commodities, geographies, markets, and prices. | Refactor `npm run test:ceda` to print explicit YES/NO, PASS/FAIL/BLOCKED for CEDA key, Auth, Commodities, Geographies, Markets, and Prices. | Run `npm run test:ceda`. |
| **AUDIT-08** | **Sell Page Default Commodity & Quantity** | `frontend/src/pages/market/index.tsx` | Market page defaulted to `Wheat` and `100` quintals even for farmers growing other crops (e.g. Cotton or Soybean). | Load active farmer's primary crop and field yield if authenticated; if guest/unconfigured, prompt crop selection. | Verify farmer with Soybean sees Soybean market comparison by default. |
| **AUDIT-09** | **Risk Assessment Arbitrary Scores** | `server/services/riskService.ts`, `server/controllers/riskController.ts` | `marketScore = 14` and `waterScore = 12` were hardcoded constants. Risk did not factor in actual farmer crop, stage, irrigation source, or soil data. | Refactor RiskService to compute scores from actual weather metrics, farmer crop stage, irrigation type, and market price trends. Return insufficient data if unconfigured. | Run authenticated risk assessment test with real metrics. |
| **AUDIT-10** | **Direct Marketplace Fallback Identities** | `server/controllers/marketplaceController.ts`, `frontend/src/pages/marketplace/index.tsx` | Controllers defaulted `buyerId` to `'user_buyer_vikram'`. Frontend modal defaulted buyer phone to `'9123456780'` and name to `'Agro Procurement Buyer'`. | Remove all synthetic fallbacks. Require authenticated user context for placing orders and viewing buyer orders. | Test unauthenticated order attempt → returns 401. Test authenticated buyer → uses genuine name/phone. |
| **AUDIT-11** | **Registration Auto-Generated Farm & Crop** | `server/controllers/authController.ts` | Registration automatically created 5-acre farm and 45-day-old Wheat crop even if user did not specify one. Buyer registration used Indore coordinates. | Only insert into `farms` and `crops` if user explicitly provided them during registration. Buyer profile only created with provided details. | Register new user without crop → verify `crops` table has 0 rows for that user. |
| **AUDIT-12** | **Prohibited Mock Imports in Production Code** | `frontend/src/pages/assistant/index.tsx` | `AssistantPage` imported `mockChatSuggestions` from `services/mock/mock-data.ts`. | Remove `mockChatSuggestions` import. Use translated quick question chips from `assistant.json`. | Grep codebase for `services/mock` → verify 0 imports in production code. |
